# API Reference

Base URL: `http://127.0.0.1:8000`. Implementation: `backend/src/hospitalcare/api/app.py`. Interactive schema: `http://127.0.0.1:8000/docs` (generated by FastAPI).

**Authentication:** `Authorization: Bearer <session token>` from `POST /api/auth/login`. Agent delegation tokens (`dlg.…`) are rejected with 401.

**Error format** (domain errors):

```json
{"error": {"code": "FORBIDDEN", "message": "role 'auditor' lacks permission 'patient:read_basic'"}}
```

| HTTP | code | Cause |
|---|---|---|
| 401 | UNAUTHENTICATED | Missing/invalid/expired/revoked token |
| 403 | FORBIDDEN | Permission missing (audited as `access_denied`) |
| 404 | NOT_FOUND | Unknown patient/encounter/review/observation/workflow |
| 409 | CONFLICT | Invalid state transition (review not pending, not approved, pending review exists, closed encounter) |
| 422 | INVALID_REQUEST | Domain validation (unknown code, out-of-range value). Schema validation errors use FastAPI's `{"detail": [...]}` shape |
| 503 | DATABASE_UNAVAILABLE | Database cannot be opened/queried |

## Patients and encounters

| Method | Path | Permission | Notes |
|---|---|---|---|
| GET | `/api/patients?q=` | `patient:read_basic` | Search by id or name |
| POST | `/api/patients` | `patient:create` | `{given_name, family_name, sex: female|male|unknown, birth_year?}` → 201, id `SYN-P-xxxxxxxx` |
| GET | `/api/patients/{patient_id}/context?encounter_id=` | `patient:read_basic` (history needs `patient:read_history`) | Same structure as MCP `get_patient_context` (see [MCP_TOOLS.md](MCP_TOOLS.md)); audited `patient_context_viewed` |
| GET | `/api/encounters?status=open|closed&patient_id=` | `patient:read_basic` | Includes `synthetic_queue_priority`, `latest_review_status` |
| POST | `/api/encounters` | `encounter:create` | `{patient_id, complaint_code, chief_complaint, complaint_source?, record_source?}` → 201 |
| GET | `/api/encounters/{id}` | `patient:read_basic` | Adds `observations`, `symptoms`, `conflicts` when the user has `patient:read_history`; `synthetic_queue`; `workflows` |
| POST | `/api/encounters/{id}/observations` | `observation:record` (+`observation:verify` to record as verified) | `{code, value, source_type, verification_status?, source_ref?}`; 422 for unknown code, non-numeric or out-of-range value |
| POST | `/api/encounters/{id}/symptoms` | `symptom:record` | `{code, present, source_type?}` |
| POST | `/api/observations/{id}/verify` | `observation:verify` | Marks active observation verified |
| POST | `/api/observations/{id}/status` | `observation:verify` | `{status: superseded|entered_in_error, reason}` |

Example:

```http
POST /api/encounters/SYN-E-0005/observations
{"code": "temperature_c", "value": 370, "source_type": "device"}

422 {"error": {"code": "INVALID_REQUEST", "message": "Temperature 370.0 is outside the data-entry range 25.0–45.0 °C; check for a typing error"}}
```

## Protocols and workflows

| Method | Path | Permission | Notes |
|---|---|---|---|
| GET | `/api/protocols` | `triage:run` | All protocol files with `valid`, `status`, `evaluable`, `sha256`, levels |
| POST | `/api/workflows` | `triage:run` | `{encounter_id, protocol_id?="SYNTHETIC-DEMO-OPD", protocol_version?="0.1.0"}` → **202** `{thread_id, status:"RUNNING"}` |
| GET | `/api/workflows?encounter_id=` | `triage:run` | Run list |
| GET | `/api/workflows/{thread_id}` | `triage:run` | `{run, state{steps[], context, evaluation, summary, review_id, review, execution, errors[], recovery, protocol_document{path, sha256, ok}}, next[], paused_for_review, recovery}` |

## Reviews and queue

| Method | Path | Permission | Notes |
|---|---|---|---|
| GET | `/api/reviews?status=` | `review:read` | Urgent first |
| GET | `/api/reviews/{id}` | `review:read` | Review + `evaluation`, `action`, `encounter`, `patient`, `queue_entry`, `priority_levels`, `summary` |
| POST | `/api/reviews/{id}/decision` | `review:decide` (session only) | `{decision: approve|reject|request_clarification|override, rationale (≥3 chars), override_priority?}` → `{review, workflow_resumed, queue_effect}`; 409 if not pending or approve without proposal |
| POST | `/api/reviews/{id}/execute` | `review:decide` | Recovery/retry of an APPROVED or EXECUTION_FAILED review. Returns `{status, duplicate, action, review, error}`; 409 if not approved |
| GET | `/api/queue` | `queue:read` | `{label:"SYNTHETIC QUEUE — not connected to any hospital system", entries[]}` |
